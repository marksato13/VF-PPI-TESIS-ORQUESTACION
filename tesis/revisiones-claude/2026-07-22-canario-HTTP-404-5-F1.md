## Valor de la etiqueta

Es defendible que una fila normal tenga `http_error_ratio_60s=1`. El objetivo es evitar la regla simplista «todo error HTTP es ataque». La interpretación depende de las demás variables: baja tasa, cinco conexiones completadas, cero RST y ausencia de señales simultáneas de enumeración.

Esta aceptación no afirma que cualquier secuencia de 404 sea benigna. Un escenario F3 de enumeración deberá diferenciarse por intensidad y contexto, sin reutilizar estas ventanas para evaluación.

## Límites no bloqueantes

Claude destacó correctamente:

- cinco solicitudes son una muestra pequeña;
- todas proceden del mismo cliente y terminan en el mismo servidor;
- las rutas `/recurso-inexistente-N` son sintéticas y repetitivas;
- las dos filas comparten historia de 60 segundos y no son observaciones independientes;
- el 0 % de paquetes entre 500–1500 bytes es esperado para respuestas pequeñas y debe complementarse con el estrato pesado ya capturado.

La primera fila no es la cola de una solicitud anterior: contiene una solicitud emitida a `03:53:49.906Z`, justo antes del límite `03:53:50Z`. La segunda ventana contiene las otras cuatro y conserva las cinco solicitudes dentro de su horizonte L7 de 60 segundos.

## Aislamiento

Claude aceptó el aislamiento efectivo porque `eth0` de Kali estaba `DOWN`, no existía ruta externa y `.113` no respondió desde VM01. Codex conserva una salvedad: mantener una IP configurada en una NIC desconectada es un riesgo latente de bypass si ESXi vuelve a conectar el enlace. No afectó esta captura, pero el gate debe comprobarlo antes de cada campaña.

El perfil mide recambio de sesiones cortas; no demuestra concurrencia, variedad de destinos ni diversidad de payload.
